# cross_embody

Decoupling Decision and Control for Cross-Embodiment Learning.
A single policy trained in Franka simulation, deployed zero-shot to a UR5e real robot without task demonstrations.

## Directory Structure

```

├── configs/
│   ├── dims.yaml         # Interface contract: shared dim spec, no module redefines it
│   └── robots.yaml       # Robot registry: add a new arm by adding an entry + a URDF
├── fk_encoder/
│   └── fk_encoder.py     # Layer 1: FK Encoder (non-learnable, pure geometry), 21-dim output
├── layer2/
│   ├── embedding.py      # Layer 2: Embedding W (21-dim FK feature -> latent z), per-robot
│   └── decoder.py        # Layer 2: robot-specific Decoder (latent -> joint angles)

│   ├── train_stage1.py   # Layer 2 Stage 1: W embedding + Franka Decoder (reconstruction)

│   └── validation/       # latent-space / reconstruction visualization tools
├── tests/
│   ├── test_fk_fr3.py    # FR3 validation (dims, m constancy, quaternion sanity)

```

## Layer 1: FK Encoder

A non-learnable, config-driven forward-kinematics encoder. It maps joint angles of
an arbitrary-DoF arm into a unified 21-dim physical feature vector, so robots of
different morphologies become comparable in the same space.

Output (21-dim): `[ p_ee(9) | v_kp(9) | m(3) ]`
- `p_ee` : EE position(3) + 6D rotation(6), expressed in the base frame
           (6D = first two columns of the rotation matrix; Zhou 2019 continuous representation)
- `v_kp` : three keyvectors (v_SE, v_SW, v_SEE), normalized by upper-arm length L
- `m`    : `[arm_ratio, workspace_r, dof_norm]`, structural constants computed once at init

### Adding a new arm (no code changes)
1. Place the URDF under `urdfs/<robot>/`
2. Add an entry in `configs/robots.yaml` specifying `urdf` / `root_link` / `arm_dof` /
   `key_links` (shoulder/elbow/wrist/ee) / `base_rotation`
3. If the robot's base axes differ from the unified convention, set `base_rotation`
   (a fixed rotation matrix)

## Layer 2: Embedding + Decoder

- `Embedding` W: per-robot projection from the 21-dim FK feature (first 18 dims, `m` dropped)
  to a 128-dim latent `z`.
- `Decoder`: per-robot translator `z + m -> q`. It only translates latent <-> joint angle,
  it does not predict the future (that is the transformer's job in Stage 2).

Stage 1 trains W + Decoder as an autoencoder with a noisy `q_ref` (σ=0.03), chosen from the
`scripts/experiments/find_noise.py` sweep as the best precision / latent-reliance trade-off.

## Running the tests

```bash
conda activate cross_embody
cd ~/cross_embody
python tests/test_fk_fr3.py    # runnable from any directory
python tests/validate_fk.py    # needs MuJoCo; writes to validation_out/
```
